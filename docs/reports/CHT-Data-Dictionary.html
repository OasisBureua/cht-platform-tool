1Summary

Most client reporting depends on three words: views, engagement and attendance. In the current code, "views" has five different meanings, "engagement" is not defined anywhere, and "attended" means "joined the Zoom session at least once, for any length of time". Every other number in the reports builds on these three, so they need to be defined first.

Views are platform-native lifetime totals

YouTube viewCount and clip view_count are cumulative counts as of the last sync, not views inside the report window. No system collects watch time. The YouTube field labelled "average view duration" actually holds the video's length.

Engagement is undefined

No repo computes an engagement count or rate. The only computed ratios are LinkedIn CTR and video completion rate. The funnel stage named "Engaged" is HubSpot landing-page views.

Attendance means any join

One Zoom join event of any duration counts as attended and verifies the registrant. If a Zoom report import exists for a program, it replaces all webhook data for that program. Attendees seen only through webhooks have no duration, so they count as 0 minutes watched.

Refresh is mostly on demand

In prod, Content Hub has no scheduled refresh: the weekday 14:00 UTC export ingest runs in dev only. YouTube and LinkedIn sync when an admin clicks Sync. Meta, livestream and survey platform data arrive by CSV upload. Nothing refreshes "daily" today.

Reports compute few numbers in code

cht-reports computes attendance rate, attendee breakdowns and survey percentages itself. Platform performance (YouTube, LinkedIn, Meta) and HubSpot data are passed to the model as raw text, so the numbers in the narrative are not calculated deterministically.

Some screens disagree

Examples: two different "total earnings" figures; video "complete" at 95% in the database but 100% in GA4; survey unlock after 60 minutes for some checks and 105 minutes for others; the funnel counts registration rows, not distinct people.

7Known limitations (consolidated)

Accuracy (affects reported numbers)

  1. Report import is all-or-nothing. One report row for a program discards every webhook or SDK attendee for that program (platform export.service.ts:496-502).
  2. Webhook-only attendance has no duration, so average minutes are understated. LEFT rows are never paired with JOINED rows.
  3. No minimum attendance duration. A 1-second join verifies attendance and unlocks the honorarium. An in-app SDK join verifies the user's own account.
  4. The Zoom webhook accepts unsigned requests when the signature header is missing (zoom-webhook.service.ts:117). A forged join could verify attendance (inferred).
  5. The packet has no date window. Registrations include pending and waitlisted.
  6. YouTube views are lifetime, and "average view duration" is actually video length.
  7. HubSpot email statistics can be multiplied across campaigns, and the generic key search can double count.
  8. The model writes the narrative numbers for platform and HubSpot data. They are not computed in code.
  9. Survey completion rate can understate the true rate or exceed 100%. Survey scores are client-supplied.
  10. Video progress unit mismatch (0–1 sent, 0–100 documented), so admin progress shows 100× too small.

Freshness

  1. Platform connectors are on demand only; Meta, livestream and survey data are uploaded manually.
  2. Hub export ingest is not triggered by attendance verification, report imports or survey submissions.
  3. Post statistics freshness is owned by ops-console and is not visible to these repos. The catalog adds up to 1 hour of cache.
  4. Zoom attendee report import is manual. Its lock is held in memory, so multiple ECS tasks could run the same import twice (inferred).

Coverage (metrics that do not exist)

  1. No engagement, no-show, unique-viewer or watch-time metric.
  2. CME credits are never issued (CMECredit is empty). Live sessions never mark an enrollment complete.
  3. AnalyticsEvent and User.lastLoginAt are never written, so user activity and recency cannot be measured.
  4. Hub's clip_analytics and campaign_analytics tables have no ingest code. Post share_count and impression_count are not exposed.
  5. Companion telemetry exists only in logs. The knowledge base has no YouTube captions yet.

JOINED / LEFTZoom participant events stored in WebinarParticipantEvent.
Report importAn admin pull of Zoom's official participant report (with durations) into Platform.
RollupThe export step that combines one person's join rows into a single attendance row.
VerifiedAttendance status that unlocks the post-event survey and honorarium.
FEEDBACK / INTAKEPost-event survey / registration survey.
Input packetPlatform's export of sessions, attendance, registrations and surveys for one campaign.
Export ingestContent Hub pulling the input packet into its export_* tables.
Report packetContent Hub's combined payload (Platform export, platform data, HubSpot, KOLs, template) consumed by cht-reports.
Platform dataPer-campaign, per-day YouTube, LinkedIn, Meta, livestream and survey rows in Content Hub.
PostOne published copy of a clip on a social platform, holding that platform's counters.
KOLKey opinion leader. A doctor featured in or relevant to the campaign.
M2MCognito client-credentials authentication between Platform and Content Hub.
Native / ComputedNative: a value passed through from a third-party API. Computed: calculated by CHT code.
